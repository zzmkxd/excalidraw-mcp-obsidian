## 如何绘制流程图

用户以自然语言描述流程。你需要将其解析为步骤、决策和分支，分配预设令牌，然后分两阶段绘制。

所有样式值来自 `clean-tech` 预设 — 禁止硬编码 hex 颜色、像素尺寸或字体值。参照下方令牌表选择正确的令牌值。

---

### 步骤 0 — 判断布局方向

根据用户描述推断布局方向：

| 用户描述特征 | 布局方向 | 主路径走向 | 备选分支走向 |
|------------|---------|-----------|------------|
| 自上而下的步骤、审批流、层层推进 | **垂直 (top-down)** | 向下 | 向右偏转再向下 |
| 从左到右的阶段、流水线、横向流程 | **水平 (left-right)** | 向右 | 向下偏转再向右 |

---

### 步骤 1 — 识别节点角色

为每个步骤选用形状和令牌：

| 用户描述 | 令牌 | 形状 |
|---------|------|------|
| 开始、触发、入口、第一步、登录页 | node:positive | 圆角矩形 (`roundness: { type: 3 }`) |
| 结束、完成、退出、结果、最终、成功 | node:negative | 圆角矩形 (`roundness: { type: 3 }`) |
| 处理、步骤、校验、检查、转换、计算、保存、发送、调用、执行 | node:primary | 普通矩形 |
| 判断、如果、是否、分支、条件、选择、检查是否 | node:highlight | 菱形 |
| 错误、异常、失败、拒绝、超时、无效 | node:negative | 普通矩形 |
| 子流程、并行、并发、分叉、汇合 | node:secondary | 普通矩形 |

不确定时默认使用 `node:primary` 普通矩形。

---

### 步骤 2 — 分配箭头

| 流向类型 | 令牌 | 标签示例 |
|---------|------|---------|
| 正常推进（步骤 → 下一步） | arrow:primary | （无需标签） |
| 决策分支（是/否） | arrow:highlight | "是", "否" |
| 错误/拒绝路径 | arrow:negative | "无效", "拒绝" |
| 可选/回退/异步 | arrow:muted | "重试", "超时" |

决策分支必须带标签（"是" / "否" 或用户的条件文本）。直通流程箭头可不标。

---

### 布局规则

- **主路径**沿流向（垂直则向下，水平则向右）
- **决策分支**：主路径继续沿流向；备选路径正交偏转（垂直布局向右偏→再向下，水平布局向下偏→再向右）
- **节点尺寸**：同层处理节点等宽（`layout.nodeW`）。菱形使用 `layout.nodeW` × `layout.nodeW`
- **标题**：居中置于流程图之上，`fontSize: 22`
- **绝不跨形状走线**：必要时用额外 `points` 绕行

---

### 绘制阶段

**阶段 1 — `batch_create_elements`（仅形状）**
1. 顶部标题文本，`fontSize: 22`
2. 所有节点按顺序：开始 → 步骤 → 决策 → 结束
3. 所有节点标签，`fontSize: 16`

**阶段 2 — `bind_arrows`（仅连接）**
4. 用 `startElementId` / `endElementId` 绑定所有连接
5. 为决策分支添加 "是"/"否" 标签，`fontSize: 12`

---

### 检查清单
- [ ] 开始和结束节点使用圆角矩形（不仅靠颜色区分）
- [ ] 决策节点使用菱形 + `node:highlight` 令牌
- [ ] 所有处理步骤等宽
- [ ] 决策分支箭头上标有 "是"/"否"
- [ ] 错误路径使用 `arrow:negative`
- [ ] 主路径沿流向；备选路径正交偏转
- [ ] 无硬编码 hex 颜色
- [ ] 无箭头跨越形状
